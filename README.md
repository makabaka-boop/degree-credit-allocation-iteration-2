# 毕业审核审计器

一门课可能同时列在多个培养模块的认可清单里,但学分只能用一次。按模块顺序贪心
分配会把本可达标的学生误判为不合格(见 `examples/contested.json`)。本工具对
课程归属做全局优化,输出归属方案、各模块缺口与 `PASS` / `SHORTFALL`。

## 分配规则

- 每门课只能**完整**分给一个合格(在其认可清单内)的模块,或不使用;
- 各模块的计入学分以其要求值**封顶**,超出部分不计入;
- 可选的 `exclusiveGroups` 声明互斥课程组(同一课程的多次修读或互斥替代课):
  同组**至多一门**获得模块归属,其余必须标为未使用;组占用状态与各模块
  封顶学分在**同一个优化**里联合求解——不能先算出旧最优分配再删去互斥课程;
- 在所有合法方案中,先**最大化计入总学分**(各模块计入学分之和);
- 提供上次归属时,再**最小化相对上次归属的改动门数**(未使用 `null` 与模块
  归属之间的互算一门,模块间调整也算一门);
- 仍有并列时,按课程 id 顺序取**归属模块 id 序列字典序最小**者,
  其中"未使用"排在所有模块 id 之后(模块 id 按字符串字典序比较,如 `"M10" < "M2"`)。

### 培养方案调整:上次归属与锁定

可选地携带 `previousAssignments`(覆盖**全部**课程的上次归属)与
`lockedCourses`(正式锁定、不得改动的课程 id):

- 锁定课程必须**保持原归属**(原归属为 `null` 即必须未使用),在动态规划中
  只有唯一一条转移;锁定、互斥组占用与模块封顶在**同一次状态搜索**里联合
  求解——不能先算出(无锁定)最优再把锁定课挪回去;
- 其余课程在三级目标下重新联合分配:总学分优先,其次尽量少改已通知学生的
  归属,最后沿用字典序裁决;
- 上次归属中某门课的原模块即使**已不在该课当前认可清单内**,输入仍合法
  (只是该课必然要改);但该课若同时被**锁定**,则为 `LOCK_CONFLICT`;
- 同一互斥组内有**两门及以上**锁定课的原归属都不是未使用时,也为
  `LOCK_CONFLICT`(锁定为 `null` 的组员不占组名额,不冲突)。

推论:把课分给任何合格模块都不会减少计入总学分,且字典序上优于"未使用",
因此未传 `exclusiveGroups` 时,最优方案的输出里不会出现未使用的课程;
传入互斥组后,同组未获归属的课程必须标为未使用(`null`)。同理,每组
恰好会有一门课获得归属(全组闲置总可以被严格更优的方案替代),输出中的
`counted` 仅在格式上保留 `null` 的可能。

## 输入(仅接受 JSON)

从标准输入或文件读取一个 JSON 对象,任何一处结构不合法即**整份拒绝**
(退出码 2,错误信息以 JSON 写到 stderr)。结构合法但锁定课程无法在当前
规则下保持原归属时,返回退出码 3,stderr 给出明确的 `LOCK_CONFLICT` 与
逐项冲突原因,stdout 不输出任何部分分配。基本输入示例:

```json
{
  "modules": [
    {"id": "M1", "required": 2},
    {"id": "M2", "required": 2}
  ],
  "courses": [
    {"id": "C1", "credits": 2, "modules": ["M1", "M2"]},
    {"id": "C2", "credits": 2, "modules": ["M1"]}
  ]
}
```

| 约束 | 说明 |
| --- | --- |
| 模块 | 2–5 个,`id` 为非空 ASCII 字符串且唯一,`required` 为 1–10 的整数 |
| 课程 | 1–16 门,`id` 为非空 ASCII 字符串且唯一,`credits` 为 1–4 的整数 |
| 认可清单 | `modules` 为非空数组,元素必须是已声明的模块 id,且不重复 |
| 互斥组 | 可选 `exclusiveGroups`,至多 3 组;每组为 `{"courses": [...]}`,含 2–3 门**已声明**课程,组内不重复,组间不得共享课程 |
| 上次归属 | 可选 `previousAssignments`,为 `{"course": ..., "module": ...}` 列表;必须**覆盖全部课程且不重复**,课程 id 须已声明,模块为已声明模块 id 或 `null`(上次未使用) |
| 锁定课程 | 可选 `lockedCourses`,为课程 id 数组(可空),元素须已声明且不重复;提供该字段时必须同时提供 `previousAssignments` |
| 严格性 | 未知模块/课程、重复 id、多余字段、缺失字段、非 JSON 输入均整份拒绝;上次归属缺项/重复/未知 id 同样整份拒绝 |

例如声明 C1、C2 互斥(同一课程的两次修读,只能计入一门):

```json
{
  "modules": [{"id": "M1", "required": 2}, {"id": "M2", "required": 2}],
  "courses": [
    {"id": "C1", "credits": 2, "modules": ["M1", "M2"]},
    {"id": "C2", "credits": 2, "modules": ["M2"]},
    {"id": "C3", "credits": 2, "modules": ["M1", "M2"]}
  ],
  "exclusiveGroups": [{"courses": ["C1", "C2"]}]
}
```

## 输出

退出码 0,stdout 输出 JSON:

- `status`:所有模块缺口为 0 时 `PASS`,否则 `SHORTFALL`;
- `total_required` / `total_counted`:要求总学分 / 计入总学分;
- `assignments`:按课程 id 排序的归属(`module` 为模块 id,未使用为 `null`);
- `modules`:按输入顺序给出各模块 `required` / `assigned`(原始归属学分)/
  `counted`(封顶后计入学分)/ `shortfall`(缺口);
- `exclusiveGroups`(**仅当输入传入该字段**):按输入顺序给出每组的
  `courses` 与 `counted`(该组最终获得模块归属的课程 id,全组未使用为
  `null`),便于教务员复核每组计入了哪一门。未传该字段时,输出与旧版
  完全一致,不含此键;
- `changes`(**仅当输入传入 `previousAssignments`**):按课程 id 顺序列出
  **实际发生变动**的课程,每项为 `{"course", "from", "to"}`,`from` /
  `to` 为模块 id 或 `null`;未变动的课程不列。锁定课程恒不出现在其中。

锁定冲突时退出码 3,stderr 形如:

```json
{
  "error": "LOCK_CONFLICT",
  "message": "locked assignments conflict with current rules",
  "conflicts": [
    {"course": "C2", "reason": "ineligible", "module": "M2"}
  ]
}
```

`conflicts` 中 `reason` 为 `ineligible`(锁定课原模块已不在其当前认可
清单)或 `exclusiveGroup`(同组两门及以上锁定课同时归属,附 `courses`
与 `locked`)。**未提供** `previousAssignments` 时,退出码与输出 JSON
逐项保持旧版不变(不含 `changes` 键)。

## 运行

```bash
python3 audit.py < examples/contested.json    # 从 stdin 读
python3 audit.py examples/infeasible.json     # 从文件读
python3 audit.py < examples/exclusive.json    # 含互斥组:C1/C2 只计入一门
python3 audit.py < examples/revision.json     # 方案调整:锁定 C1 后联合重分配
```

## Docker Compose

```bash
docker compose build
docker compose run --rm -T audit < examples/contested.json   # 审核
docker compose run --rm test                                 # 运行 pytest 对拍
```

(`run` 需要 `-T` 关闭伪终端,stdin 重定向才能生效。)

  互斥组联合优化(不能在旧最优上删课)、组内并列裁决、封顶模块不再吸收

  总学分优先于少改门、锁定翻转达标状态、锁定与互斥组联合重排(非先求旧最优

  组内未知/重复课程、组间共享课程、组字段多余/缺失、组数超限等

  未知/重复、仅有锁定无上次归属等 15 种非法调整输入;
- **命令行**:stdin/文件读取、非 JSON 与非法文档的拒绝行为、未传新字段时
  输出逐字节不变、非法互斥组整份拒绝且 stdout 不产生方案;上次归属正常输出
  `changes`、非法调整输入退出码 2、`LOCK_CONFLICT` 退出码 3 且不输出部分
  分配(含资格冲突与同组双锁两种原因)、锁定翻转达标状态。

## 实现说明

`audit.py` 仅用标准库。求解用动态规划:状态为(各模块已计入(封顶后)学分
元组, 互斥组占用位掩码),逐门课转移——组内已有一门归属时,其余组员只能
未使用;锁定课程只允许保持原归属这一条转移;每个状态保留字典序最小的
(相对上次归属的改动门数, 归属记号序列),最后在计入总学分最大的状态中
取该组合最小者——锁定、组占用与模块封顶因此在同一次状态搜索里联合完成,
不会出现"先求旧最优再把锁定课挪回去"。锁定冲突(失去认可资格、同组双锁)
在搜索前检测,冲突即整体拒绝。规模上限(5 模块 × 要求 10、16 门课、至多
3 个互斥组)下最坏约数秒。
